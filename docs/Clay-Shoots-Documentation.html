◎ Clay Shoots

Live clay-shooting scoring for clubs: an iPhone/iPad scoring app, a club website with results and leaderboards, and automatic emails and social posts.

Document covers the system as built in the ClayClubsShoots repository. Everything described here is in the code; items that need a decision or that are untested are flagged in Known limitations.

1. Overview

Scoring app

SwiftUI app for iPhone and iPad. Scores by voice, keyboard or buttons. Several devices share one shoot at the same time.

Website

Node/Express site with results, leaderboard, shoot history, roster management, social posting and account tools.

Automation

Results emailed to each shooter, results posted to social media, daily backups and subscription reminders.

Typical flow

  1. Club admin signs up on the website, adds the roster of members and guests, and creates an API key.
  2. Each scoring device connects to the server once (URL, key and certificate fingerprint).
  3. On the shoot day, one device starts a New Shoot, picking shooters and options. Other devices join automatically.
  4. Shooters are scored by voice or taps. Scores upload as they are entered; the website updates live.
  5. When every stand is locked, the shoot is finished: final results are spoken, emailed to shooters and posted to social accounts.

3. Installation & running

Server

cd ClayClubsShoots
npm install
cp .env.example .env      # then edit .env
npm start                 # production run
npm run dev               # auto-restart on file changes

On start-up the server prints its address (e.g. https://192.168.1.100:3000) and the server key fingerprint to enter in the phone app.

HTTPS & key pinning

The server runs HTTPS only. For a private network it creates a self-signed certificate in data/tls/. The phone app does not trust certificates by authority; instead it pins the SHA-256 of the server's public key. Enter the fingerprint printed at server start-up in the app's server settings. If the certificate is ever regenerated, the fingerprint changes and each device must be updated.

Building the iOS app

  1. Open ios/ClayShootScoreApp.xcodeproj in Xcode (the project uses a file-system synchronised group, so new Swift files are picked up automatically).
  2. Select the device and build, or from a terminal: 
    cd ios
xcodebuild -project ClayShootScoreApp.xcodeproj -scheme ClayShootScoreApp \
  -destination "id=<DEVICE-UDID>" -configuration Debug \
  -derivedDataPath /tmp/ClayShootScoreApp-<UDID> -allowProvisioningUpdates build
xcrun devicectl device install app --device <UDID> /tmp/ClayShootScoreApp-<UDID>/Build/Products/Debug-iphoneos/*.app
xcrun devicectl device process launch --device <UDID> com.clivetalbutt.ClayShootScoreApp --terminate-existing
  3. Bundle identifier: com.clivetalbutt.ClayShootScoreApp. The app needs microphone and speech-recognition permission.

5. Website guide

The top navigation shows the current shoot name, your email and role. Menus: Shoot clubs (super admin only, top level), Dashboard ▾ (Results, Leaderboard) and Account ▾ (Shooters, Social, Sign out).

Results (/results)

  • Choose a shoot – a custom dropdown showing up to 10 shoots at a time, scrolling for more. The selected shoot is highlighted in gold.
  • Admins see a red ✕ against each shoot. Click ✕ to mark one or several shoots (struck through in red), then press Delete marked (n) and confirm in the on-page dialog. Deleting removes the shoots and all their results permanently.
  • Results table: one column per stand, total (net total on handicap shoots), average %, place (🥇🥈🥉 for the top three) and CPSA class. Columns sort; Filter shooters searches by name; Share gives a link for the shoot.
  • The page refreshes automatically when new scores arrive, and jumps to a newly started shoot.

Dashboard (/dashboard)

Shoot list with search, sortable columns, select-all and bulk delete (admins). Also shows account status and, for admins, the API key controls.

Shooters (/shooters)

The club roster of members and guests, current or expired.

  • Email is required for members; optional for guests. Guests without an email receive no results emails.
  • Guest book – tick "Has signed the guest book" for guests; shown as a column.
  • Names are tidied automatically (capitalised). Members' emails are verified by a link (valid 7 days, resend after 5 minutes).
  • Each club has a paid-for member and guest allowance; adding beyond it is blocked (see billing).
  • The app reads the same roster, so shooters added in either place appear in both.

Social (/social)

Connect up to 10 accounts. After a shoot finishes, results are posted automatically. Platforms: Discord, Slack, Telegram, Mastodon, Bluesky, Facebook and X. Credentials are stored encrypted, and each account records the outcome of its last post. A failed post never blocks a results upload.

Account (/account)

Change password, set up two-factor authentication, manage the API key (super admin), see subscription status and billing, and run or restore backups.

Shoot clubs (/admin/clubs) super admin

Lists every club account. Open a club to "act as" it (a banner shows Viewing as … with a Return button), set subscription state, and run the renewal reminder sweep on demand.

6. iPhone / iPad app

Connecting to the server

Open Server settings (toolbar). Enter the server URL (e.g. https://192.168.1.100:3000), the API key from the website and the key fingerprint. A club code connect flow (/api/v1/clubs/lookup, /connect) is also supported. The app shows live sync status, and keeps scores on the device if the server is unreachable, retrying until they are delivered.

Starting a shoot

The home screen appears when no shoot is on the scoresheet. It has New Shoot and a Previous shoots menu. If another device already has a current shoot, this device joins it automatically.

New Shoot opens Who is shooting?:

SettingDetail
ShootersTick members and guests from the roster. Add new people with the roster form (members need an email; guests do not).
StandsNumber of stands in the shoot (1–25), 10 targets each by default.
Shooting orderAs entered (the order ticked – default), Alphabetic or Random. Applied when the shoot starts.
Spoken feedbackOff, Enthusiastic or Sarcastic – the style of remark spoken when a shooter finishes a stand.
Announcer voiceDefault (British), or up to five female and five male English voices installed on the device. Picking one plays a sample. Remembered per device.
Handicap shootOptional; see handicaps.

Press Start Shoot. Once started, shooters, stands, order and handicap are locked.

Scoring

  • Score table – pinned shooter names with a running total, one cell per target per stand, and a Place column once finished. The current shooter's name is bold; the current stand and cell are outlined.
  • Entry methods – voice (always listening on the score screen), keyboard (hit/miss keys), on-screen Hit/Miss buttons, and tapping a shooter to select them.
  • Stand summary card – after a shooter finishes a stand, a card shows their score, who is next, and (if one more is possible) "Possible n". Input pauses while it is shown; a tap dismisses a timed card without counting as a Hit or Miss.
  • Auto-locking – a stand locks when any later stand has scores; the last stand locks after 15 s without edits. Locked stands cannot be changed.
  • Pairs – score two targets at once ("pair hit", "lost pair").
  • Manual mode – a mode toggle switches off voice recognition for button-only scoring.

Voice control

Recognition uses Apple's Speech framework and is matched by sound, not exact spelling (SpeechMatcher.swift), so "it" for "hit" or "Jon" for "John" still works. Voice listening is only active on the score screen – it is switched off in the roster, settings and previous-shoot screens, in the background, and while the app is speaking.

SayEffect
“hit”Scores the next target as a hit.
“miss” / “lost”Scores the next target as a miss.
“pair hit”Next two targets are hits.
“pair lost” / “lost pair”Next two targets are misses.
“<name>” or “shooter <name>”Switch to that shooter (first or full name).
“<name> hit”Switch shooter and score in one go.
“stand 3”, “next stand”Move to a stand.
“stand 3 john hit”Stand, shooter and score together.
“clear shooters”Remove every shooter.
“clear shooter <name>”Remove that shooter.
“clear score [<name>] [stand n]”Wipe scores for the current/named shooter, all stands or one.
Add Shooters mode: “<name>, pause, <name>…”Say each name with a pause between; press Finish.

"Clear" commands run about a second after you stop speaking, so pause briefly after one. The in-app help (? button) lists the same commands.

Spoken announcements

  • Voice – chosen in setup; default is the best British voice installed. For the best quality download an Enhanced/Premium voice under Settings → Accessibility → Spoken Content → Voices.
  • Hit / Miss are spoken for keyboard and button entries (not voice entries, to avoid echo).
  • End of stand – the shooter's score and who is next; with a feedback style selected, a remark based on the score band (perfect, ≥90%, ≥70%, ≥50%, below). Three phrases per band per style, chosen at random.
  • Final results – spoken when the shoot finishes, best first, one utterance per place so nothing is cut off. A tie is grouped: “Joint 1st, Alan, Bob and Chris, with 40.” On handicap shoots scores are net.
  • The microphone is paused while the app speaks and resumes afterwards.

Handicap shoots

  1. Switch on Handicap shoot in setup and choose Average taken over: All time, Last year (default), Last 3 months, Last 1 month, Last 6 shoots, Last 3 shoots (the "last N shoots" options use each shooter's own most recent N shoots).
  2. On Start Shoot the app fetches each shooter's average score per stand from the server.
  3. Handicap = floor(average per stand × number of stands), a whole number. Net total = total − handicap.
  4. Net totals drive places everywhere (app, website, emails, speech).
The averages include earlier handicap shoots. The chosen period is not shared between devices; the handicap values themselves are uploaded and shared.

Multi-device sync

  • A club has one current shoot (the newest unfinished one). Every device shows it.
  • Devices upload changes immediately and poll the server every 2 seconds, merging in stands scored elsewhere.
  • Each device only writes the stands it owns (ownedStands); remote stands are merged in without overwriting local unsent edits.
  • A blank device picks up a shoot another device started. A device in the middle of setup (roster sheet open or adding shooters) is not pulled away. A device with unsent changes is not overwritten.
  • An offline outbox stores the latest full scoresheet and retries until delivered.
  • If another device finishes the shoot, this device shows the locked final results too.

Finishing a shoot

Complete means every target is scored; Finished means complete and every stand locked. On finishing: final results are announced, the shoot is uploaded as complete, shooters with an email are sent their results, and social accounts are posted to. The toolbar offers Submit results, then new shoot, Excel export and New Shoot (with confirmation).

Previous shoots

The home screen's Previous shoots menu lists finished shoots (newest first, up to 60). Selecting one opens a read-only results sheet with per-stand scores, totals (net if handicap) and places.

8. API reference

All /api/v1 calls use HTTPS and Authorization: Bearer <API key> (except the club lookup/connect calls). Bodies are JSON. Requests are rate-limited.

10. Email, social & reminders

  • Results email – on completion each shooter with a verified address gets their own results (stand scores, total, place with medal, class). At most 50 per shoot; outcomes are logged. Guests without an email are skipped.
  • Social posts – a results summary posted to each enabled account once per completed shoot.
  • Renewal reminders – a sweep every 6 hours emails clubs 30, 14, 7 and 1 days before the subscription ends, when it lapses, and a week later (stops after 60 days). Each reminder is sent once per subscription period.
  • Incomplete uploads (complete:false) never trigger emails or posts.

11. Billing & allowances

  • Pricing is per head per year: £1 per member, 50p per guest. A club buys an allowance of members and guests; the roster cannot exceed it. Increase/decrease requests are held until paid.
  • Providers: Stripe (cards, Apple/Google Pay), PayPal, GoCardless (Direct Debit), Square, Mollie. Return pages verify with the provider, so a first payment works even if webhooks cannot reach the server. A 3-day grace period applies.
  • With no provider configured, every account has full access. The super admin and older accounts have no limit.

12. Security

  • HTTPS only; self-signed certificates are protected by public-key pinning in the app.
  • Strict Content-Security-Policy (helmet): inline scripts are blocked, so page scripts live in public/*.js.
  • CSRF token on every website POST; rate limits on login, API, upload and polling.
  • Passwords hashed with bcrypt; optional TOTP two-factor; API keys stored hashed; 2FA and social secrets encrypted with APP_ENCRYPTION_KEY.
  • Role checks enforced on the server (delete is admin-only; super-admin routes guarded).
  • Social webhook targets are validated against private/internal addresses.

13. Backup & restore

  • A daily JSON backup of every table (except sessions) is written to the backup folder; 30 daily copies are kept.
  • Restoring first takes a prerestore safety copy (10 kept). Run or restore from Account → Backups (super admin).
  • For a manual copy, stop the server and copy data/app.db (and the data/tls folder to keep the same fingerprint).

nohup npm start > /tmp/clay-server.log 2>&1 &

17. Known limitations

  • The handicap period and shooting-order choices are not stored on the server or shared between devices.
  • Handicap averages include earlier handicap shoots.
  • Net = total − handicap is the implemented interpretation.
  • The microphone may occasionally hear the app's own speech.
  • Several recent features (sync fixes, voice gating, voice picker, joint announcements, new-shoot fix on iPhone) were built and installed but not fully tested on devices.
  • Joint wording is applied to the leaderboard and spoken results, not to the on-screen result tables.
  • The code has not yet been pushed to GitHub (credentials needed).
